# Карта общих терминов

> Status: Draft  
> Scope: переносимая карта общих терминов для документации  
> Role: reusable glossary, который можно переносить между проектами вместе с папкой `docs/terms/common/`

## 1. Назначение

Этот документ хранит общие термины, которые не привязаны жестко к одному проекту и могут переиспользоваться в других документационных пакетах.

Он нужен для:
- lazy loading при чтении документации человеком и агентом;
- progressive disclosure от краткого определения к детальной term page;
- переноса общей терминологии между проектами на уровне одной папки;
- уменьшения дублирования в архитектурных и методологических документах.

Project-specific понятия должны жить отдельно в `docs/terms/project/terms_map.md`.

## 2. Как пользоваться этим файлом

Рекомендуемый маршрут чтения:
1. сначала открыть эту карту и прочитать краткое определение;
2. если у термина есть отдельная term page, перейти к ней только при необходимости;
3. затем вернуться в исходный архитектурный или методологический документ.

## 3. Правила для common terms

- в этот файл попадают только reusable terms, которые можно безболезненно переносить в другой проект;
- если термин требует большого раскрытия, для него создается отдельная страница в `docs/terms/common/terms/`;
- общие документы должны по возможности ссылаться на эту карту, а не повторять длинные определения;
- project-specific смыслы не должны смешиваться здесь с локальными договоренностями проекта.

## 4. Канонический реестр общих терминов

| Термин | Краткое определение | Детальная страница |
| --- | --- | --- |
| Source of Truth | Канонический источник состояния системы или документационного слоя, относительно которого проверяются derived representations и runtime projections. | none |
| portable references | Stable identifiers и relative references, которые можно безопасно переносить между машинами и окружениями без привязки к machine-specific physical paths. | none |
| Service-local Runtime State | Внутреннее operational state сервиса, включающее records, snapshots, jobs, caches, indices и другие служебные структуры. | none |
| Runtime Materialization State | Environment-facing runtime projection, которую потребляет внешняя system или tool и которую можно rebuild из canonical source layers. | none |
| graph projection | Derived graph representation, которая строится из source artifacts и используется для navigation, provenance, traceability и analysis. | none |
| drift detection | Сравнение desired state и materialized state для обнаружения mismatch, stale artifacts, manual edits или других признаков рассинхронизации. | none |
| reconcile | Процесс повторного сканирования source state, rebuild derived structures и при необходимости repair materialized runtime state. | none |
| file-first workflow | Подход, в котором основным способом authoring и versioning остаются обычные files, а service interfaces выступают как вспомогательный слой. | none |
| lazy loading | Подход к чтению документации, при котором человек или агент сначала открывает обзорные артефакты, а затем только нужные детальные страницы. | none |
| progressive disclosure | Многоуровневая подача документации от короткой карты и glossary к более глубоким specialized documents и contracts. | none |

## 5. Что не должно попадать в common terms

В эту карту не стоит помещать:
- локальные domain terms конкретного проекта;
- project-specific роли агентов;
- имена конкретных слоев проекта;
- частные договоренности о workflow, если они значимы только внутри одного проекта.

Такие понятия должны жить в `docs/terms/project/terms_map.md`.

## 6. Политика обновления

Обновляй эту карту, если:
- один и тот же общий термин начал использоваться в нескольких документах или проектах;
- термин оказался переносимым и перестал быть локальной договоренностью;
- появилась новая reusable term page в `docs/terms/common/terms/`;
- нужно синхронизировать общую терминологию между несколькими проектами.

Эта карта является переносимой точкой входа для общих терминов и может копироваться между проектами вместе с папкой `docs/terms/common/`.
