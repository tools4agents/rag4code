## Детали кандидатов

- **Neo4j Community** – хорошо известная графовая СУБД с Cypher. В OSS-издании поддерживается только одна основная БД (system+default)【2†L301-L307】, поэтому для изоляции проектов придётся запускать отдельный контейнер Neo4j с собственным томом на каждый проект. Поддерживается Docker (официальный образ, см. пример монтирования `/data`【16†L539-L547】). Python-драйвер `neo4j` (bolt) стабилен и поддерживает транзакции и bulk-операции (MERGE). Встроенные UI: Neo4j Browser (без лицензии) и Neo4j Visualization Library (NVL); также есть сторонние JS-библиотеки (Neovis, Sigma.js, Cytoscape.js) для встраивания визуализации. Основные риски – необходимость множества инстансов (перегрузка) и GPLv3-условия【8†L246-L248】.

- **Memgraph** – платформа с in-memory-ориентированным движком и поддержкой Cypher. Community-редакция под BSL 1.1【22†L50-L58】 (очень ограничивает открытость). Мульти-БД лишь в Enterprise, поэтому аналогично одному проекту – один контейнер. Поддерживает Docker, предлагает Memgraph Lab для визуализации (но он привязан к лицензии). Python-драйвер – `pymgclient` или тот же Neo4j-driver (Bolt)【25†L453-L460】. Данные кешируются в памяти с записью логов на диск, доступны snapshot/WAL механизмы сохранения. Минус – не полностью «open source» лицензия, ограниченная функциональность бесплатной версии.

- **Apache AGE (на базе PostgreSQL)** – расширение PostgreSQL для графовых запросов в открытом Cypher【32†L39-L44】. Абсолютно открыто (Apache 2.0). Проекты-Графы могут создаваться в любой базе Postgres через `create_graph()`【34†L106-L113】; по проектам можно создавать отдельные схемы или даже БД. Легко задеплоить в Docker, используя официальный Postgres (с расширением AGE) и монтировать volume для PG. Python-доступ – через `psycopg2` или `apache-age-python`【37†L312-L320】. Backup/restore – стандартный PostgreSQL (pg_dump, pg_basebackup). Визуализации нет готовой, но можно использовать универсальные графовые библиотеки. Это новое решение (релиз 2026) – пока не так широко распространено, но дает гибкость и транзакционность Postgres.

- **NebulaGraph** – распределённая графовая СУБД с лицензией Apache 2.0【44†L74-L79】. Поддерживает несколько пространств/графов («spaces»), которые можно использовать для раздельного хранения проектов внутри одного кластера. Docker-образ официально доступен (многокомпонентный: meta/graph/storage), с поддержкой volume. Язык запросов – nGQL (совместимый с OpenCypher). Python-драйвер – `nebula3-python` (графовые операции через gRPC). Есть веб-UI *NebulaGraph Studio* (открытый, Apache-2.0)【48†L438-L439】 для создания схем и визуализации. Также NebulaGraph Dashboard Community Edition доступен для мониторинга. Минусы: относительно сложная установка (несколько сервисов) и ресурсозатратность для простого одиночного проекта.

- **OrientDB** – мульти-модельная БД (граф+документ) под Apache 2.0【61†L27-L31】. Сервер может содержать несколько баз; в каждой – своя графовая структура. Имеются Docker-образы, поддержка монтирования тома для хранения файлов БД. Запросы – с помощью расширенного SQL (+ Gremlin TinkerPop). Python-драйверы (`pyorient`, `oriento`) есть, но проект уже не слишком активно развивается. Есть встроенный визуальный интерфейс OrientDB Studio (открытый). Ограничения: старее и менее популярна на рынке, требует изучения собственных моделей.

- **JanusGraph** – распределённая графовая БД (Apache 2.0【58†L208-L216】) как верх над хранилищами (Cassandra/HBase). Для простого использования в Docker придётся поднимать много сервисов (набор сервисных бэкэндов). Запросы – Gremlin (есть `gremlin-python`), транзакции поддерживаются, данные долговременно хранятся в выбранном бэкенде. Визуальной оболочки нет. Сильный недостаток – сложность развертывания и отсутствие Cypher (наши инструменты больше рассчитаны на Cypher).

- **Dgraph** – ранее считался open-source, но сейчас перешёл на BSL (не соответствует требованиям). Имеет свои UI (Ratel) и GraphQL-интерфейс, но из-за лицензирования не подходит.

*(При желании стоит упомянуть ArangoDB: до версии 3.12 – под Apache 2.0, с 3.12 перешла на BSL【63†L1-L6】. Arango – мульти-модель с графовыми возможностями (AQL), но переход на BSL ставит ее в разряд «не открытых».)*

## Визуализация графов

Для веб-frontend мы не привязываемся к UI поставщика. Можно использовать популярные JS-библиотеки, например [Cytoscape.js](https://js.cytoscape.org/), [Sigma.js](http://sigmajs.org/) или [vis-network](https://visjs.github.io/vis-network/) и другие. Они позволяют рисовать узлы/рёбра, выполнять интерактивную фильтрацию и трэвёрсал. 

Из графовых БД готовые UI и плагины:
- *Neo4j*: **Neo4j Browser** (free) и [Neovis.js](https://github.com/neo4j-contrib/neovis.js) для интеграции. 
- *Memgraph*: **Memgraph Lab** (проприетарный, не используем).
- *NebulaGraph*: **NebulaGraph Studio** (Apache 2.0, [GitHub](https://github.com/vesoft-inc/nebula-studio)【48†L438-L439】). 
- *OrientDB*: **OrientDB Studio** (открытый Web UI).
- *AGE/Postgres, Dgraph*: встроенного UI нет – использовать общие библиотеки.

В целом рекомендуется отделить СУБД от визуализации: хранить граф в БД, а frontend строить на выбранных JS-решениях.

## Persistency и бэкапы

Все указанные СУБД позволяют монтировать в контейнер Docker тома для сохранения данных:
- **Neo4j/Memgraph/OrientDB**: монтируются каталоги `/data` (и `/logs`)【16†L539-L547】. После остановки контейнера данные сохраняются.
- **PostgreSQL + AGE**: как обычный PG – используется volume для `PGDATA`, бэкапы через `pg_dump`/`pg_restore`.
- **NebulaGraph**: сохраняет метаданные и данные на смонтированные диски (настройки через Docker Compose). Имеются команды snapshot.
- **JanusGraph**: зависит от бэкенда (например, Cassandra хранит свои файлы, монтируемые отдельно).
Бэкап/restore может делаться с помощью штатных инструментов (дампы, копирование томов, утилиты DBMS). Во всех случаях «включили/выключили → docker up» – данные остаются благодаря примонтированным томам.

## API / SDK

Все системы имеют драйверы для Python:
- **Neo4j/Memgraph**: официальный драйвер Bolt (`neo4j` PyPI). Поддерживаются транзакции, параметризированные запросы, MERGE/UPSERT, массовая загрузка через Cypher или CSV.
- **Apache AGE**: стандартный PG-драйвер (`psycopg2`) – Cypher-запросы выполняются в SQL (`SELECT * FROM cypher(...)`). Могут использоваться batch-вставки SQL.
- **NebulaGraph**: `nebula3-python` или `nebula2-python`. Поддерживает транзакции и DML (insert/update/delete, upsert через nGQL).
- **OrientDB**: `pyorient` (для старых версий) или **Python OrientDB driver**, поддерживают SQL-подобный синтаксис.
- **JanusGraph**: `gremlin-python` (сокет Gremlin Server). Поддерживаются транзакции в рамках Gremlin-сессии.
Во всех случаях доступны основные операции: создание/удаление вершин и рёбер, поиск смежных узлов, трэвёрсал по глубине. Для инкрементальной синхронизации можно использовать команды удаления рёбер и последующей вставки новых связей из исходных данных.

## Рекомендации

**Для MVP** оптимальным выбором будет **Apache AGE (PostgreSQL+AGE)**. Причины:
- Полностью открытое решение (Apache 2.0) и использует проверенный движок PostgreSQL.
- Легко обеспечить изоляцию: можно создать одну БД Postgres на проект (или схему), установить расширение AGE и создать графы【32†L39-L44】【34†L106-L113】. Физически при деплое в Docker достаточно поднять один контейнер PG и внутри управлять несколькими БД.
- Полноценная транзакционная поддержка и надежная система бэкапов («pg_dump/pg_restore»).
- Полезно тем, что в будущем можно сочетать графовые и SQL-данные без дублирования системы.
- Для синхронизации Markdown-ссылок хватит базовых Cypher-запросов (MATCH по рёбрам и узлам).  
- Гибкость использования Python и привычных инструментов (psycopg2, SQLAlchemy и т.д.).

В качестве **альтернатив** стоит рассмотреть:
- **Neo4j Community**: зрелая СУБД с мощными возможностями, но потребует отдельного контейнера на проект. Годится, если не смущает GPL-лицензия. Позволяет использовать знакомый Cypher и драйверы.
- **NebulaGraph**: для будущего масштабирования. Поддержка OpenCypher-подобного синтаксиса и веб-интерфейс Studio хороши, но поднять кластер сложнее. Можно внедрять, когда потребуется масштаб (MVP-версия тяжеловата).

Остальные (Memgraph, OrientDB, JanusGraph) менее приоритетны: Memgraph из-за лицензии BSL, OrientDB – из-за упадка развития, JanusGraph – из-за сложности.

## Интеграция и проектная изоляция

В рамках архитектуры HyperGraph придерживаемся подхода «1 проект → 1 SQL DB + 1 Graph DB». При этом:

- Для **PostgreSQL/AGE**: каждому проекту соответствует своя бД. Сервис переключается на нужный PG-регион с помощью `SET DATABASE` или нового подключения (можно хранить строку подключения `project_id → db_name`). В выбранной бД вызывается `SET search_path = ag_catalog, "$user", public` и работают с конкретным графом. Относительные пути заметок храним как свойства узлов (например, свойство `path`), так как «корень» известен проекту.
- Для **Neo4j/Memgraph**: каждой проекту – свой контейнер или экземпляр (docker-compose с префиксом). Серверное API `switch(project_id)` переводит в нужный Bolt-URI (например, `bolt://neo4j-project123:7687`).
- Для **NebulaGraph**: можно создать отдельный `space` на проект и при подключении указывать нужное пространство (`USE project_space`). Это логически изолирует данные.
- Для хранения относительных путей: в узле или связях добавляется свойство `rel_path`. Например, узел заметки имеет свойство `path='notes/alpha.md'` (от корня проекта). При построении графа ссылка `[ ... ](docs/beta.md)` создаёт ребро между узлом `alpha.md` и `beta.md`. Broken-link можно обнаружить при попытке `MATCH (a)-[r:LINK]->(b)` где `b` не найден.

Таким образом, механика переключения проекта – простое переключение контекста базы данных или контейнера, а все пути остаются относительными, поскольку хранятся в рамках выбранной БД.

## Источники

Основные источники информации использованы для сравнения лицензий, архитектуры и возможностей СУБД:

- Neo4j: лицензия GPLv3【8†L246-L248】, ограничения Community (нет Multi-DB)【2†L301-L307】, Docker volumes【16†L539-L547】.  
- Memgraph: лицензия BSL (см. официальный раздел «Legal»【22†L50-L58】), информация о multi-tenancy (Enterprise)【23†L444-L452】.  
- Apache AGE: описание как PG-расширение【29†L60-L64】【32†L39-L44】, создание графов【34†L106-L113】.  
- OrientDB: лицензия Apache 2.0【61†L27-L31】.  
- NebulaGraph: лицензия Apache 2.0, поддержка OpenCypher【44†L74-L79】, веб-UI Studio (Apache 2.0)【48†L438-L439】.  
- ArangoDB: (лицензия Apache 2.0 до версии 3.12).  

Дополнительная информация взята из официальных руководств и документации SGBD, а также из обсуждений сообществ (см. табл. ссылок ниже).
